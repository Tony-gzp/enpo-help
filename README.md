另外我还顺手处理了几件你没提但会遇到的事：

- **QQ 号加密存储**：数据库里存的是密文，页面默认打码，点「查看 QQ 号」才在浏览器里还原，防批量抓取。
- **校园网共享 IP 问题**：很多学校整个校区共用一个出口 IP，如果按 IP 严格限流会误伤同学，所以默认限制放宽到 30 次/小时。
- **首次部署零手工**：后端第一次收到请求时会自动建表并导入初始数据，不需要你敲 SQL 命令。
- **黑夜模式白屏闪烁**：主题判断提前到页面渲染之前，夜间用户不会看到一闪而过的白屏。
- **离线兜底**：后端连不上时，网站会自动降级成「离线预览模式」，页面照样能看，并在顶部提示。

## 二、三分钟先看效果

### 方式 A：在线模式（推荐，功能完整）

这样跑起来的是一个**真正的动态网站**：数据存在本机数据库里，就跟你部署到网上之后一模一样。

1. 在网站文件夹里按住 `Shift` + 鼠标右键 → 「在此处打开 PowerShell 窗口」
2. 输入：

```powershell
node tools/dev-server.mjs
```

3. 浏览器打开 <http://localhost:8788>
4. 后台在 <http://localhost:8788/admin.html>，默认口令 `enpo-admin-2026`
5. 看完按 `Ctrl + C` 关掉服务器

> 数据库文件在 `tools/_dev/data.db`。删掉它再启动，就会重新初始化一份干净的 82 条数据。

### 方式 B：离线模式（不启动服务器）

直接双击 `index.html` 也能看，但这时数据只能存在你自己的浏览器里，其他同学看不到你提交的内容，页面顶部会有黄色提示条。

## 三、网站结构

| 页面 | 文件 | 作用 |
|---|---|---|
| 欢迎页 / 免责声明 | `index.html` | 第一次进入时显示，勾选同意后才能进站；之后自动跳过 |
| 导航页（首页） | `home.html` | 顶部标题 + 各模块入口（每个按钮带一句介绍）+ 实时数据小结 + 底部免责声明 |
| 常见问题 | `faq.html` | 9 个分类、22 条问答，支持关键词搜索 |

| 我发布的 | `books-mine.html` | 发布者本人改内容、改「是否已出」、删除 |
| 培养方案（三级） | `plan-2026.html` / `plan-2025.html` / `plan-2024.html` | 选学期 → 选专业组 → 看课程与教材 |
| 必选通识课 | `general-edu.html` | 思维导图 + 学分要求 + 7 个模块 41 门课程 |

## 五、后台怎么用

打开 `admin.html`，输入口令（默认 `enpo-admin-2026`，**请务必改成自己的**）。

### 七个标签页

**📊 概览** — 各类数据统计和常用操作入口。

**🕵️ 待审核** — 同学提交的出书信息会先到这里。
- 点「✅ 通过」后才会出现在前台；
- 点「❌ 不通过」可以填原因，发布者会在「我发布的」里看到；
- 发布者自己改过内容的条目会出现在「需要复核」列表里。

**📚 全部条目** — 搜索、修改、删除。「✏️ 修改内容」可以改除「是否已出」以外的所有字段。
> 「是否已出」**只有发布者本人能改**，你在后台提交修改也会被服务器拒绝（这是刻意设计的，防止站主误改状态）。

**💡 建议箱** — 完全匿名的留言。可以标记已处理、写处理备注、导出成 txt。留言里没有联系方式，无法回复到个人。

**✏️ 内容编辑** — 四个子标签页：
- 常见问题：增删分类、增删问答，图标可以选择；
- 校内网站：增删分组、增删网站，**图标用图标选择器挑**（内置 60 个常用图标，分 5 组）；
- 通识课：增删模块、增删课程、改学分要求；每门课有「**是否还能选**」下拉，标成「不可选」后
  页面上的课程名会自动加红色删除线并注明原因（用来标记以后不再计入学分的课）；
  思维导图用 JSON 编辑（结构特殊）；
- 培养方案：按「年级 → 学期 → 专业组」三级导航，直接改课程表；
  教材一行一本，格式 `书名 | 主编 | 版次 | 出版社`；备注支持换行。
  提示：把「要求」填成「二选一必修」「24选1必修」这类文字，页面会自动把这些课合并成一块。

每个内容块底部都有「💾 保存并发布」「⬇️ 导出文件」「↩️ 恢复默认」。

**🎛️ 选项管理** — 改出书表单的选项：专业、年级/类型、是否已出、书籍清单（按学期分组，每行一个）。改完立即生效。

**⚙️ 数据与设置** — 导出备份（JSON / CSV）、导入恢复、导入初始数据、生成口令哈希、清空本机数据。

## 六、把网站放到网上（Cloudflare，全程免费）

你之前选了 GitHub Pages，但静态托管做不到「别人提交 → 你审核 → 所有人可见」。
所以推荐用 **Cloudflare Pages + D1 数据库**：

| 优点 | 说明 |
|---|---|
| 免费 | Pages 静态托管不限流量；D1 免费额度 5 GB 存储、每天 500 万次读，校园网站用不完 |
| 国内可访问 | 比 GitHub Pages 稳定，且自带 CDN |
| 安全 | 口令、权限、频率限制都在服务端，前端拿不到也改不了 |
| 一次部署 | 前端和后端在同一个项目里，推代码就自动发布 |
| 自带防护 | 可以免费开 DDoS 防护和人机验证（Turnstile） |
| 不用命令行 | 建库、绑定、配口令全在网页上点几下完成 |

### 👉 详细步骤看这里：**[部署教程.md](部署教程.md)**

那份教程是**单独写给完全没部署过网站的人**的，从注册账号到验证成功，
每一步都写了「在哪里点、填什么、看到什么算成功」，还有常见卡点的排查方法。

这里只给一个极简流程概览：

| 步骤 | 做什么 |
|---|---|
| 1 | 注册 GitHub，新建仓库，把网站文件拖拽上传 |
| 2 | 注册 Cloudflare |
| 3 | Cloudflare → **Storage & Databases → D1** → 建一个叫 `enpo` 的数据库 |
| 4 | Cloudflare → **Workers & Pages → Create → Pages → Connect to Git** → 选仓库 → 构建命令留空、输出目录填 `/` → 部署 |
| 5 | 项目 **Settings → Functions → D1 database bindings** → 变量名填 `DB`，选 `enpo` |
| 6 | 项目 **Settings → Variables and Secrets** → 加 `ADMIN_PASSWORD` = 你的口令 |
| 7 | **Deployments → 最新一条 → ⋯ → Retry deployment**（第 5、6 步改完必须重新部署才生效） |
| 8 | 打开 `你的网址/admin.html` 登录验证 |

> **建表不用你操心**：后端第一次收到请求时会自动建表，并导入 82 条初始数据。
> 所以第 8 步第一次打开网站时会稍微慢一两秒，之后就正常了。
>
> 更安全的做法是只存哈希：把 `ADMIN_SALT` 和 `ADMIN_PASSWORD_HASH` 两个变量都配上。
> 哈希值可以在后台「数据与设置 → 修改口令」里生成。
>
> 喜欢命令行的同学，仓库里有一份 `wrangler.toml.example`，
> 改名成 `wrangler.toml` 并按里面的注释填写即可（默认不启用，不影响上面的流程）。
### 第 7 步：以后怎么更新

- **改内容** → 直接在后台改，立即生效，不用做任何事；
- **改代码/样式/数据文件** → 在 GitHub 上编辑或用 `git push`，Cloudflare 会自动重新部署（1～2 分钟）。

## 七、可选：开启 Turnstile 人机验证

Cloudflare Turnstile 是免费的验证码，用户**只需要点一下复选框**，体验比图形验证码好得多，
而且不需要注册额外账号。

1. Cloudflare 后台 → **Turnstile** → **Add site**，域名填你的 `xxx.pages.dev`。
2. 会得到两个值：
   - **Site Key**（站点密钥）→ 填到 `assets/js/config.js` 的 `turnstileSiteKey`，然后推代码；
   - **Secret Key**（密钥）→ 在 Pages 项目里加环境变量 `TURNSTILE_SECRET`，然后重新部署。
3. 如果你用了自己的域名，记得同时更新 `_headers` 里的 CSP，加上：
   `script-src 'self' https://challenges.cloudflare.com; frame-src https://challenges.cloudflare.com;`

**不配也能用**，只是少一层防护——现有的蜜罐字段、时间陷阱、同源校验、频率限制、
机器人 UA 拦截依然生效。

## 八、备选：只用 GitHub Pages

如果你暂时不想折腾云端数据库，也可以只用 GitHub Pages：

1. 仓库 → Settings → Pages → Source 选 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`。
2. 等一两分钟，网址形如 `https://用户名.github.io/仓库名/`。

**但要清楚它的限制**：GitHub Pages 只能托管静态文件，跑不了后端，
所以网站会自动降级成**离线模式**——每个人看到的是自己浏览器里的数据，
你收不到别人提交的出书信息和建议。

这种模式适合「先让大家看看长什么样」，不适合真正投入使用。

## 九、防爬虫和隐私保护做到了什么程度

**做到了：**

| 措施 | 说明 |
|---|---|
| 服务端拦截（在线模式） | 所有校验都在服务器上做，绕过网页直接调接口也改不了不该改的东西 |
| 机器人 UA 拦截 | `curl`、`python-requests`、`HeadlessChrome`、`Puppeteer` 等直接 403 |
| 同源校验 | 写操作必须带正确的 Origin，别的网站没法替你提交 |
| 频率限制 | 按 IP 限流（出书 30 次/小时、建议 20 次/小时、查询 200 次/小时） |
| 蜜罐字段 | 藏一个真人看不见的输入框，机器人一填就被判定 |
| 时间陷阱 | 打开页面不到 4 秒就提交 → 拒绝；超过 12 小时的旧页面也拒绝 |
| 中文算术验证 | 题目用汉字写（「七 加 六 等于几」），需要认识汉字才能答对 |
| QQ 号加密 | 数据库里是密文，页面源码里也不含明文，点击才在浏览器还原 |
| 口令安全 | 只存哈希（可选），`timingSafeEqual` 防时序攻击，连错 5 次锁 10 分钟 |
| 反收录 | `robots.txt` 拒绝全部爬虫 + 每页 `noindex`，搜索引擎不会收录 |
| 零第三方 | 全站没有任何外部 CDN / 统计脚本，不存在第三方偷偷收集数据 |
| 匿名建议 | 意见建议不收集任何身份信息，站主也无法知道是谁提的 |

**没做到、也做不到的（务必知道）：**

1. **`robots.txt` 是君子协定**，正规搜索引擎会遵守，恶意爬虫不会。真正保护 QQ 号的是加密 + 打码 + 点击才显示。
2. **QQ 号点开后就是明文**。任何人只要肯手动点，都能看到。这是「方便同学联系」和「防抓取」之间必须做的取舍。
3. **不要把这个网站的链接发到大群、贴吧、微博**。`noindex` 能防搜索引擎，防不住有人手动转发。小范围在班级群、宿舍群流传最安全。
4. **站主口令是唯一的管理凭证**，丢了别人就能改你的内容。建议设长一点，并且定期导出备份。

## 十、数据备份与恢复

**备份**：后台 →「数据与设置」→「导出全部数据（JSON）」，另存到网盘或邮箱。
也可以导出 CSV，用 Excel 打开查看和编辑。

**恢复**：把导出的 JSON 内容粘贴回「导入数据」→ 点「导入出书信息」。
已存在的记录（同 ID）会被覆盖，其余保留。

**建议**：每学期末导出一次；做任何批量操作前先导出一次。

## 十二、常见问题排查

**Q：页面顶部出现黄色「离线预览模式」提示条？**
说明前端连不上后端。检查：
- 是不是直接双击打开的 HTML 文件？那就用 `node tools/dev-server.mjs` 或部署到网上；
- 如果是线上，打开 F12 → Network，看 `/api/health` 是不是 404 或 500。
  404 通常是 `functions/api/[[path]].js` 没上传成功。

**Q：登录后台提示「后台还没有设置口令」？**
在线模式下口令来自环境变量。去 Cloudflare 项目设置里加 `ADMIN_PASSWORD`，然后重新部署。

**Q：提交出书信息提示「请求被拒绝：检测到非浏览器访问」？**
你用了无头浏览器或脚本提交。用正常浏览器打开就没问题。

**Q：数据文件改完没生效？**
后台改的内容存在云端，会覆盖文件里的默认值。
去「内容编辑」里点「↩️ 恢复默认」，或者直接在后台改。

**Q：想重新生成一份干净的数据？**
删掉 `tools/_dev/data.db`（本地）或到后台点「清空本机浏览器数据」；
线上数据请用后台「⚠️ 危险操作」里的删除功能，或用命令行
`npx wrangler d1 execute enpo --remote --command "DELETE FROM books WHERE origin='seed'"`。

**Q：网站首页/二手教材显示"信息不见了"或者内容是空的？**
浏览器里可能存着**上个版本**的本地数据。现在的代码会自动识别并迁移
（把老结构转成新结构，并换成新的初始数据）。如果还是不对，到后台
「数据与设置 → 危险操作 → 清空本机浏览器数据」，然后刷新页面即可。

**Q：`python tools/parse-xlsx.py` 报错找不到 openpyxl？**
说明用的 Python 没装这个库。用系统自带的 Python 时执行
`pip install openpyxl` 即可。

## 十四、已知限制

1. **意见和建议只存在云端数据库**，如果你不部署后端（只用 GitHub Pages），
   就收不到同学的建议。这是静态托管的固有限制。
2. **QQ 号点开即明文**，无法做到既方便联系又完全防抓取。
3. **书籍清单是按教材名匹配的**：82 条初始记录里，只有备注里写全了书名的那些
   自动识别出了书籍（36 本），其余的显示在备注里，不影响阅读。
4. **培养方案数据不完整**：原表格只有 2026 级的大一两个学期、2025 级的大二上、
   2024 级的大三上。缺的部分需要你补充。
5. **没有账号系统**是刻意的设计，好处是同学不用注册就能用；
   代价是「谁提交的」只能靠编辑码来认，编辑码丢了就找不回来（可以找站主删除）。
6. **Cloudflare 在国内的可访问性**总体不错，但偶尔会有波动。
   如果发现经常打不开，可以再考虑配一个自己的域名。
